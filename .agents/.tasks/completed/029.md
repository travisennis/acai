# Fix unbounded step accumulation in agent state

## Problem

In `source/agent/index.ts:186-187`, the agent loop pushes `{ toolCalls, toolResults }` entries into `this._state.steps` every iteration but never clears them. Each item is a small object, so the leak is not catastrophic, but over long sessions (hundreds of iterations) unnecessary memory accumulates and the `state` object is serialized/sent to the TUI for display.

## Relevant files

- `source/agent/index.ts` — `run()` method and `resetState()`

## Implementation notes

1. In `resetState()`, already clears `this._state.steps = []`. The issue is not reset but accumulation within a single `run()` call.
2. The purpose of `steps` is to track tool calls per step for the active `run()` invocation. Since `run()` is called fresh each time the user submits input, `steps` starts fresh each call — the leak is within a single `run()` of many iterations.
3. Do not clear `this._state.steps` before yielding `agent-stop`; the footer still reads `agentState.steps.length` and reduces over `steps` for the displayed tool-call total, so clearing the array would make final footer stats incorrect.
4. Preferred fix: add aggregate counters to `AgentState` for total step count and total tool-call count, update those counters as the loop runs, and update the footer to render from the counters instead of deriving totals from the retained `steps` array.
5. Keep `steps` as recent per-step detail only and cap it to a small bounded history, such as the last 5 or 10 entries. This preserves useful live/debug detail without letting the array grow with configured `loop.maxIterations`.

## Acceptance notes

- [x] `this._state.steps` is capped to a bounded recent history within a single agent run.
- [x] Agent state still exposes accurate total step count and total tool-call count for the full run.
- [x] The TUI footer renders accurate step and tool-call totals after long multi-iteration runs.
